# Presentation figures — assets + raw data

This directory holds the PNG figures used in the intermediate supervisor
presentation (see `local comments/projectoverview/claude.md` §28), plus
under `data/` the raw source values behind every figure so they can be
regenerated or restyled in another tool (Excel, PowerPoint chart,
seaborn, TikZ, whatever) without re-running training or re-parsing HDF5.

## PNG figures at a glance

| File | Produced by | What it shows |
|---|---|---|
| `loss_v1_v4.png` | `python -m model.src.plot_training` | Loss curves for Phase B v1/v2/v3/v4 on one log-y axis, with MSE and CE baseline lines. |
| `gradnorm_v1_v4.png` | same | Grad-norm curves for v2/v3/v4 (v1 predates gradient-norm logging). Shows v4 grad norms are 100× smaller than v2/v3. |
| `class_imbalance.png` | `python -m model.src.plot_class_imbalance` | 4-panel bar chart: real training-data class distribution (99.4 % empty) vs what v2/v3/v4 actually generate. |
| `real_vs_v4.png` | `python -m model.src.real_vs_generated --ckpt … --out …` | 4×2 grid of triple-orthographic projections: nearest real training building vs Phase B v4 sample, per condition. |

logging was added to `train.py` after v1's collapse — this absence is
itself a talking point for the presentation ("we added grad-norm
logging because v1 collapsed and we couldn't see why"). See
`claude.md` §26.11.

## Regenerating everything

Run these three lines from the repo root with the venv active:

```bash
# 1. Re-dump the raw CSVs / JSON  (few seconds)
python -m model.src.dump_figure_data --out-dir figures/data

# 2. Re-render the three matplotlib figures  (few seconds each)
python -m model.src.plot_training --out-dir figures
python -m model.src.plot_class_imbalance --out figures/class_imbalance.png

# 3. Re-render the real-vs-v4 comparison  (~30 s, needs GPU + v4 ckpt)
python -m model.src.real_vs_generated \
    --ckpt model/checkpoints/phase_b_v4/ckpt_100000.pt \
    --out  figures/real_vs_v4.png
```

## Extra figures worth building (for the final defence, not the intermediate)

- **Occupancy trend over training** — `occupancy_trend.csv` already has
  the data. A line chart per condition per version would show v4 stable
  at 0.7–2.5 %, v2/v3 stuck at 70–82 %.
- **Isometric render of v4 final samples** — polished 3D voxel views.
  Command:
  ```bash
  python -m model.src.render \
      --samples model/checkpoints/phase_b_v4/samples/step_100000/samples.npz \
      --out    figures/isometric_v4_step100k.png \
      --isometric --cols 4 \
      --suptitle "Phase B v4 — final samples at step 100 000"
  ```
- **Progression figure** — same condition, same seed, watching the model
  learn across training steps:
  ```bash
  python -m model.src.progression \
      --samples-dir model/checkpoints/phase_b_v4/samples \
      --out figures/progression_v4.png \
      --seed 42 --n-cols 6
  ```

## Provenance notes

- Grad-norm logging (v2 onwards) reports the *pre-clip* norm as returned
  by `torch.nn.utils.clip_grad_norm_()`, so entries above `grad_clip=0.5`
  in v2/v3/v4 are clipped events. See `claude.md` §26.11.
- The class-frequency dump samples 200 random real buildings; run
  `--n-real 500` for a smoother estimate.
- `real_vs_v4_metadata.json` is deterministic given the current manifest
  because the matching function is a total order.
- File paths in this doc are relative to the repo root
  (`/home/ge27lof/Documents/github/urban-auto-vox-rs-master/`).
